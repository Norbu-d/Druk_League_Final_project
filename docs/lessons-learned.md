# SWE303 — Lessons Learned

**Status:** draft compiled from the project's own records (`progress.md`, the defect log and CI history) on 28 Nov 2026. The team confirms or amends each item at the final retrospective. Opinions are not recorded here until the team has given them.

| # | What happened (evidence) | Effect | Lesson / what we would do next time |
|---|---|---|---|
| L1 | The repository's first commit is dated 12 Oct; most work landed in Sprint 4 (108 commits, 32 PRs). See the [project management plan](project-management-plan.md) §5. | Early sprints produced little to review; integration and QA were compressed into the last weeks. | Start the repository and the CI pipeline in Sprint 1 and merge small vertical slices every sprint, so the sprint review always has something to demo. |
| L2 | 20 services were planned at once (risk R1, High/High from the start). | The service shells came quickly, but the cross-service flows (registrations, public views, sign-up) were exposed to the web app only on 28 Nov. | Plan by user journey rather than by service: a journey that works end to end before more services are added. |
| L3 | The Registration service existed, but the BFF never exposed it, while fixture generation used only approved registrations (D-008). | Teams added on the website could never get fixtures. Nobody noticed, because each service passed its own tests. | Add one end-to-end acceptance test per key journey early. Unit coverage alone (80%+) did not find this gap. |
| L4 | The running containers had been built on 10 Nov from older code. A viewer could add players and shirt number 120 was accepted (D-010). | The deployed demo did not match the reviewed code. | Rebuild every image from the release commit before each demo, and make "images rebuilt from commit X" part of the Definition of Done for a release. |
| L5 | `/auth/refresh` was missing from the frontend's API allowlist (D-006). | Sessions silently expired after 30 minutes. | When a security allowlist changes, add a test for every route the client uses (now covered in `tests/frontend`). |
| L6 | Building about 30 images in parallel failed on a laptop; the same images built one at a time. | A wasted build cycle. | Cap parallelism (`COMPOSE_PARALLEL_LIMIT=4`) and let CI, not laptops, be the main image builder. |
| L7 | faasd needs Linux and containerd, so it could not run on the team's Windows machines (spike recommended in `progress.md` §11.7, never done). | Serverless was postponed to the last week. | Do the risky technology spike (risk R7 in the proposal) in Sprint 1, as the proposal itself said. |
| L8 | Documents (WBS, risk register, test plan) were written early and not updated, so on 28 Nov they still said "CI pending" although CI existed. | Reviewers would see out-of-date status. | Update the status documents at every sprint review, from the same evidence used for the Jira board. |
| L9 | Real-stack acceptance runs were recorded with exact checks, results and the revision (`progress.md` §58–59). | Defects found during acceptance (D-010) could be fixed and re-verified quickly. | Keep this practice: every claim of "done" carries its evidence and date. |
